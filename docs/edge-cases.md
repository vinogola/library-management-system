# Edge-case tables

One table per endpoint, written before the code. Each row: the request, the status the client should get, and what produces that status. Verified by curl.

**Who produces a status** (a status only reaches the client if some code produces it):
- **Nest default**: 200 for GET/PATCH/DELETE, 201 for POST.
- **`ParseIntPipe`**: 400 when the `:id` param is not a whole number. Negative integers pass.
- **`ValidationPipe`** (DTO rules, `whitelist` + `forbidNonWhitelisted`): 400 for a bad body. The handler never runs.
- **Own code**: `NotFoundException` (404) and `ConflictException` (409), thrown from the service.
- **Anything unrecognised that is thrown**: generic 500, details only in the server log.

**Prisma error codes:** `P2002` unique taken, `P2025` row to update/delete not found. A RESTRICT violation carries no Prisma code: it arrives as `PrismaClientUnknownRequestError` (Postgres `23001`), so the service matches its message text.

## Genres

"Seen" = run by curl. All "yes" rows were run on 2026-11-25 with a local throwaway script (39 checks, all matched). A dash means the row needs the DB stopped and was not run.

### `GET /genres/:id`
Reads only; no body; never changes the table.

| # | Request | Code | Produced by | Seen |
|---|---|---|---|---|
| 1 | `/5` (exists) | 200 | Nest default | yes |
| 2 | `/9999` (valid integer, no row) | 404 | `NotFoundException` (own `if (!genre)` guard) | yes |
| 3 | `/-5` or `/0` | 404 | same guard; the pipe accepts any integer | yes |
| 4 | `/abc` or `/1.5` | 400 | `ParseIntPipe` | yes |
| 5 | `/99999999999` (too big for the DB integer) | 500 | uncaught DB error | yes |
| 6 | DB down while the app is running | 500 | generic error; real cause in the backend log only | - |
| 7 | DB down at startup | no response | app exits (`onModuleInit` fails, fail-fast) | - |

Notes:
- `findUnique` returns `null` for a missing row. `null` is a fulfilled Promise, so without the guard the client gets 200 and an empty body.
- Empty input is `GET /genres` (the list route): `200 []`, not a 400.

### `POST /genres`
Body needs only `name` and `slug`; `id` is autogenerated.

| # | Case | Code | Produced by | Seen |
|---|---|---|---|---|
| 1 | all valid | 201 | Nest default | yes |
| 2 | required field missing / empty body | 400 | `ValidationPipe` | yes |
| 3 | wrong type | 400 | `ValidationPipe` | yes |
| 4 | empty string `""` | 400 | `ValidationPipe` (`@IsNotEmpty`) | yes |
| 5 | `id` in the body | 400 | `ValidationPipe` (`forbidNonWhitelisted`) | yes |
| 6 | duplicate `name` | 409 | own `catch` (`P2002`) | yes |
| 7 | duplicate `slug` | 409 | own `catch` (`P2002`) | yes |

Notes:
- A plain `create` on a duplicate throws; Nest does not turn that into 409 by itself. Only your `catch` does.
- `id` in the body is rejected (not silently stripped). My decision, 2026-11-17.

### `PATCH /genres/:id`
Changes only the fields sent, so every DTO field is optional.

| # | Request | Code | Produced by | Seen |
|---|---|---|---|---|
| 1 | `/5`, `{name:"X"}` | 200 | Nest default | yes |
| 2 | `/5`, `{}` or only `name` | 200 | DTO fields optional (partial update) | yes |
| 3 | `/` (no id) | 404 | Nest, no matching route | yes |
| 4 | `/abc` or `/1.5` | 400 | `ParseIntPipe` | yes |
| 5 | `/-78` or `/999` (valid integer, no row) | 404 | `NotFoundException` (from `P2025`) | yes |
| 6 | `/99999999999` | 500 | uncaught DB error | yes |
| 7 | `{name:99}` | 400 | `ValidationPipe` (`@IsString`) | yes |
| 8 | `{id:3}` | 400 | `ValidationPipe` (`forbidNonWhitelisted`) | yes |
| 9 | malformed JSON | 400 | body parser | yes |
| 10 | name or slug already taken | 409 | `ConflictException` (from `P2002`) | yes |
| 11 | `{name:""}` | 400 | `ValidationPipe` (`@IsNotEmpty`) | yes |

Notes:
- `update` throws `P2025` for a missing row; it does not return `null`. The service must catch it.
- `return await` inside the `try`: a plain `return` would leave the `try` before the Promise settles, and the `catch` would never run (404 would become 500).
- In the catch helper, unknown errors are thrown, never returned. A `return error` makes a fulfilled Promise: 200 with the error as the body.
- Two PATCHes at once on one row both return 200; the last write wins.

### `DELETE /genres/:id`
Removes the whole row. (Clearing one field is a PATCH with `null`, and needs an optional column.)

| # | Request | Code | Produced by | Seen |
|---|---|---|---|---|
| 1 | `/5`, genre has no books | 200 | Nest default | yes |
| 2 | `/` (no id) | 404 | Nest, no matching route | yes |
| 3 | `/abc` or `/1.5` | 400 | `ParseIntPipe` | yes |
| 4 | `/-78` or `/999` (valid integer, no row) | 404 | `NotFoundException` (from `P2025`) | yes |
| 5 | `/99999999999` | 500 | uncaught DB error | yes |
| 6 | `/5`, genre still has books | 409 | `ConflictException` (DB's RESTRICT refusal, matched by message text) | yes |

Notes:
- RESTRICT is enforced by the database, not by the service. The service never counts books; it receives the DB's error and translates it. A count-first check would still leave a 500 when a book is added between the count and the delete.
- Matching on message text breaks if Prisma rewords the error. Rerun `docs/curl-genres.sh` after upgrades.
- DELETE has no body, so there are no body rows.

## Books

### `POST /books`
Required: `title`, `author`, `genreId`. Optional: `isbn`, `publisher`, `publicationDate`, `language`, `totalCopies` (defaults to 1). `id` is autogenerated.

Rules (my decisions, 2026-11-24): `totalCopies` is an integer from 1 to 1000. `publicationDate` is checked for format only, no range. A `genreId` that points at no genre is a 400 (a bad reference in the request), not a 409.

"Seen" = run by curl. A dash means the row is written but not run yet.

| # | Case | Code | Produced by | Seen |
|---|---|---|---|---|
| 1 | all valid | 201 | Nest default | body seen, 201 inferred |
| 2 | `title`, `author` or `genreId` missing; empty body `{}` | 400 | `ValidationPipe` | - |
| 3 | wrong type, `genreId = "fiction"` | 400 | `ValidationPipe` (`@IsInt`) | - |
| 4 | empty string `""` on `title`, `author`, `isbn`, `publisher` or `language` | 400 | `ValidationPipe` (`@IsNotEmpty`) | - |
| 5 | `id` or any unknown field in the body | 400 | `ValidationPipe` (`forbidNonWhitelisted`) | yes (by accident) |
| 6 | duplicate `isbn` | 409 | own `catch` (`P2002`) | yes |
| 7 | `totalCopies = 99999999999` (does not fit `Int`) | 400 | `ValidationPipe` (`@Max`) | - |
| 8 | `totalCopies = -9` or `0` | 400 | `ValidationPipe` (`@Min`) | - |
| 9 | `totalCopies = 1` and `1000` | 201 | Nest default | - |
| 10 | `totalCopies = 1001` | 400 | `ValidationPipe` (`@Max`) | - |
| 11 | `totalCopies = 2.5` | 400 | `ValidationPipe` (`@IsInt`) | - |
| 12 | `publicationDate = "2099"` (not a full date) | 400 | `ValidationPipe` (`@IsDateString`) | - |
| 13 | `publicationDate = "2099-01-01"` (future, well formed) | 201 | Nest default | - |
| 14 | `genreId = 9999`, no such genre | 400 | own `catch` (`P2003`) | yes |
| 15 | `isbn` omitted on two books | 201 both | Nest default | seed shows 16 null `isbn` rows |
| 16 | duplicate `isbn` and missing `genreId` together | 409 | own `catch` (`P2002`) | yes (DB reported the unique rule first) |

Notes:
- `@IsOptional()` skips only `undefined` and `null`, so `isbn: ""` still reaches `@IsNotEmpty()`. Without it, the first `""` would be stored and a second would give a 409 over a blank value.
- `publicationDate` reaches the service as a string. The service converts it with `new Date(...)` because Prisma's `DateTime` wants a real date, and I expect it to reject a date-only string (not yet run).
- A rejected insert still uses up an id: the sequence isn't rolled back, so id 33 is missing.
- The FK to a missing genre arrives as `P2003` on insert. The RESTRICT refusal on genre delete arrives as an unlabelled `23001`. Same constraint, two different errors.

### `GET /books/:id`
Rules (my decisions, 2026-11-25): an id the database can never hold is a 400 (client error), not a 500. No database state could ever make it valid.

"Seen" = run by curl. A dash means the row is written but not run yet. The route does not exist yet, so nothing below can be run.

| 2 | `/abc` or `/2.5` | 400 | `ParseIntPipe` | - |
| 3 | `/9999` (valid integer, no row) | 404 | `NotFoundException` (own `if (!book)` guard) | - |
| 4 | `/-9` or `/0` | 404 | same guard; the pipe accepts any integer | - |

- `GET /books/` with no id matches `GET /books` (the list). It belongs in that table, not here.
- Row 5 is a known gap. The same fix would cover the Genre `:id` routes (rows D5 and the 500s in PATCH and DELETE).
